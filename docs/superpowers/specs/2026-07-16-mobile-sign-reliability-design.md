# 手机签名可靠性修复设计

## 目标

修复绩效考核任务详情中的手机签名流程，使签名会话在多实例部署、服务重启、数据库失败、权限变化、重复发起和弹窗关闭重开场景下仍保持一致，并确保签名人身份、消息投递结果和前端展示可信。

## 范围

- 手机签名会话持久化和一次性消费。
- 手机签名查询、提交和桌面端轮询语义。
- 员工与上级签名的最终权限复核。
- 桌面签名人与手机签名人的身份一致性。
- 飞书签名消息投递结果。
- 签名图片格式、大小和必填校验。
- 签名弹窗的提交、刷新、轮询和卸载生命周期。
- 失效链接、权限按钮和解锁规则测试。

不改变绩效考核主状态机：

`self_review -> pending_sign -> supervisor_review -> supervisor_sign -> completed`

## 数据模型

新增 `assessment_sign_session` 表：

- `id`: UUID 主键。
- `token_hash`: token 的 SHA-256 摘要，唯一索引，不保存明文 token。
- `instance_id`: 考核实例 ID。
- `sign_type`: `self` 或 `supervisor`。
- `user_id`: 发起签名的认证用户。
- `user_name`: 发起时的认证用户名，仅用于页面展示兜底；最终签名再次使用当前认证上下文。
- `status`: `pending`、`succeeded`、`failed`、`expired`。
- `expires_at`: 过期时间。
- `consumed_at`: 成功签名时间。
- `failure_reason`: 最近一次失败原因，限制长度。
- `_created_at`、`_updated_at`: 系统时间字段。

token 继续使用 32 字节随机数。服务端只使用 SHA-256 摘要查询数据库。会话默认有效期为 5 分钟。

## 后端流程

### 创建会话

1. 校验实例状态、签名类型、签名字段和当前用户操作权限。
2. 创建数据库会话。
3. 使用服务端校验过的应用地址生成手机链接。
4. 等待飞书消息发送完成。
5. 发送失败时删除本次未使用会话并向前端返回错误；不得提示已发送。

同一实例、签名类型和用户允许存在多个未过期会话。任意一个会话成功后，其他会话通过实例签名字段被识别为已完成，不依赖各自是否被消费。

### 获取会话

1. 按 token 摘要读取会话。
2. 校验当前登录用户与会话用户一致。
3. 若已过期，将状态更新为 `expired`。
4. 查询实例状态和签名字段。
5. 返回明确状态：`pending`、`succeeded`、`expired`、`invalid` 或 `forbidden`。
6. 只有 `pending` 返回员工姓名、周期和签名类型；移动端不会为失效状态展示签名板。

### 提交签名

1. 校验 token、当前用户和签名图片。
2. 开启数据库事务并锁定会话行和实例行。
3. 再次校验会话状态、有效期、实例状态和当前用户权限。
4. 以当前认证用户姓名作为签名姓名，不接受客户端覆盖。
5. 写入签名、推进实例状态、写审计日志，并将会话状态改为 `succeeded`。
6. 任一步失败则整个事务回滚，会话保持 `pending`；可重试的数据库错误不会销毁 token。
7. 业务状态已变化时，将会话标记为 `failed` 并返回明确失败状态。

### 桌面轮询

轮询查询会话和实例，不以 token 是否存在判断结果：

- `pending`: 继续轮询。
- `succeeded`: 关闭弹窗并刷新详情。
- `expired`: 停止轮询，提示重新发起。
- `failed`、`invalid`、`forbidden`: 停止轮询并显示对应错误。

## 权限与身份

- 员工签名：最终提交时必须仍是实例员工本人。
- 上级签名：最终提交时必须仍是发布时上级、当前直属上级或全局管理员。
- 手机接口必须校验登录用户与会话用户一致。
- 桌面和手机签名均忽略客户端 `signName`，统一使用认证上下文中的 `userName`。
- 员工端操作按钮与上级端一样，必须同时满足 `my_assessments.edit` 权限。

## 签名图片

- `signImage` 必填。
- 只接受 `data:image/png;base64,` 或 `data:image/jpeg;base64,`。
- 解码后的图片最大 1 MiB。
- 拒绝空白、格式错误或超限数据。
- 数据库仍保存 data URL，以保持现有详情和导出逻辑兼容。

## 前端生命周期

- 提交评分以进入签名状态时，不使用会卸载整个详情页的刷新流程。
- 评分提交成功后直接生成手机会话；最终签名完成后再刷新详情。
- 弹窗关闭、token 变化、重新发起和组件卸载时都清理当前轮询。
- 每个轮询闭包持有自己的 interval 句柄，旧轮询不能清理新轮询。
- 消息投递失败时恢复可发送状态，保留桌面手写签名能力。
- 移动端根据明确会话状态展示签名板、成功页或失效页。
- 画布尺寸变化时清空签名状态，避免显示空白画布却提交旧图片。

## 测试

新增或调整测试覆盖：

- 会话 token 只存摘要。
- 会话过期、无效、用户不匹配和成功状态。
- 数据库失败后 token 仍可重试。
- 成功事务同时推进实例、写审计并消费会话。
- 最终提交重新校验员工和上级权限。
- 客户端签名姓名不能覆盖认证用户。
- 缺失、非法和超限签名图片被拒绝。
- 飞书消息失败不返回发送成功。
- 首次发送不会因详情刷新卸载弹窗。
- 关闭重开不会遗留多个轮询。
- 移动端失效链接不展示签名板。
- 员工操作按钮遵循编辑权限。
- 修正解锁规则测试的模块导入。

## 兼容与迁移

- 保留现有 `sign-session` API 路径，扩展响应状态，减少调用面变化。
- 现有网页直接签名 API 保留，但服务端改为认证姓名并强制图片校验。
- 旧内存 token 在部署后失效，用户重新发起即可；不迁移短期内存数据。
- 新迁移只增加签名会话表，不修改已有考核实例数据。
